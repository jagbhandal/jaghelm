# JagHelm — STRIDE threat model

A one-page model of JagHelm's real trust boundaries. JagHelm is a **single-user,
single-instance** homelab dashboard: a React SPA served by an Express server that
proxies Prometheus/cAdvisor/Kuma and 35+ third-party app APIs, persists config to
YAML/JSON files, and stores credentials AES-256-GCM-encrypted. It is designed to
run on a **trusted LAN**; several defaults assume that (see KNOWN-ISSUES.md).

## Trust boundaries / assets

1. **Browser ↔ server** — header-token sessions (`x-auth-token`), no cookies (CSRF-immune).
2. **Server ↔ disk** — `data/services.yaml`, `data/display-config.json`,
   `data/secrets.json` (encrypted), `data/auth.json` (scrypt hash),
   `data/config-version.key` (0600), cron history.
3. **Server ↔ backends** — Prometheus/Kuma (operator-configured, trusted) and
   user-configured integration URLs (untrusted target).
4. **Assets**: the admin password hash, the at-rest credential store + its KDF
   salt + `DASH_SECRET`, and the metrics/config the dashboard exposes.

## STRIDE

| Threat | Vector | Mitigation (in code) | Residual / notes |
|---|---|---|---|
| **S**poofing | Forge a session; brute-force the admin password | scrypt + timing-safe compare (`auth/passwords.js`, `auth/routes.js`); per-IP **and** global login limiter + failure-delay floor (`auth/rateLimit.js`); signing out revokes the session on the server, so a token copied before it (a HAR file, a proxy log, a screenshot) stops working (`POST /api/auth/logout`, #507) | Open-by-default when no `DASH_PASS` — loud boot warning; LAN-only assumption |
| **T**ampering | Corrupt config/secrets store; torn write on crash | Atomic temp→fsync→rename writes (`util/atomicWrite.js`); copy-on-read config so a route can't mutate shared state; zod validation + reserved-key reject on config writes; no writer saves over a `services.yaml` that doesn't parse, so a hand edit gone wrong is never replaced by the last good config (`config.js` `writeConfig`, #423) | External edits to `services.yaml` are intentionally honored (watcher) |
| **R**epudiation | "I didn't probe that host / change that" | Structured JSON access log (`accessLog.js`): at the default `LOG_LEVEL=info`, 5xx, 4xx, slow requests and every write (any method but GET, HEAD and OPTIONS: method, path and status, sign-ins included); fast successful reads only at `LOG_LEVEL=debug`; `/metrics`, `/api/health` and `/api/readyz` only when they fail. Config saves (`config.js`, which covers integration save and delete) password changes and sign-outs (`auth/routes.js`, the user and never the token) log their own info line; audit log on the integration test probe (host + result); `jaghelm_auth_failures_total` metric | Single-user, so attribution is coarse. A write's access-log line names its method, path and status, not what changed (a secret set or deleted, display config, todos, uploads, push registration, a cron job deleted), and a config save logs only that `services.yaml` was saved |
| **I**nfo disclosure | Leak credentials in logs/errors; read secrets/config unauthenticated; an integration target redirects to another origin to collect its credential (a header, a key in the URL, or a login body) | `redactSecrets()` at the fetch egress, and on every string the logger writes (`util/logger.js`): a URL's password (any scheme; a user with no password, and every userinfo of a URL the parser refuses, whole), secret query values and http(s) query strings; a request error shows a credential filled into an endpoint as its placeholder before any of that runs (`shownUrl`, `integrations/lib/http.js`); the access log records only the path, without the query string, fragment or an absolute-form URL's userinfo (`accessLog.js`); a redirect to another origin forwards only an allowlist of non-credential headers (`CROSS_ORIGIN_SAFE_HEADERS` in `util/safeFetchCore.js`), and a request whose URL carries the credential (query-auth presets such as SABnzbd, Tautulli and Emby; a `{token}`, `{password}` or `{username}` endpoint placeholder) follows no redirect to another origin at all (`credentialInUrl`, set where the URL is built); a `307`/`308` keeps a request's body but never re-sends it (a session login's username and password) to another origin; all three make one exception, an `http://` to `https://` upgrade on the same host and port, which re-sends to that host what was just sent to it; fail-closed `/api/secrets` (403 until a password is set); per-install KDF salt; secrets never returned (only key names); the config read (`GET /api/services/config`) answers each credential in `services.yaml` (a value under a credential's name such as `password`, `token`, `apikey` or `secret`, plaintext or `$secret:` reference; a header value under `extraHeaders`; any `loginBody`; an endpoint with a key in its query; a value an endpoint fills in through a `{name}` placeholder) as `{ "$stored": true }`, and the write puts the stored value back in each marker's place (in an array, the element with the same name, id or key, never by position), refusing a marker anywhere the read would not put one, so it can't echo a credential or move one to another key or element (`util/configMask.js`); the config read's ETag, the version of `services.yaml` (credentials in it), is an HMAC-SHA256 with 32 random bytes per install (`data/config-version.key`, 0600, made on first start, never logged or answered; not `DASH_SECRET`, which the installs keeping plaintext credentials lack), so a version kept in a HAR file or a screenshot can't be used to test guesses at a credential offline (#423) | `/metrics` is public (counts/timings, no secrets) — Prometheus must reach it. `/api/icons/cached` is public, so anyone who can reach the port can tell which icons are already cached (the `X-Icon-Cache` header, or the time a response takes) and from that infer which services the dashboard shows; accepted, as the icons are public and the endpoint has to be. A key written into a custom integration's URL or endpoint by hand, or filled from a placeholder other than `{token}`/`{password}`/`{username}`, is not known to be a credential, so such a request still follows a redirect to another origin; the config read masks one in an endpoint, a placeholder's value or the URL, and the integration save and connection test refuse a URL that carries a key or password (#422), and one already stored is never requested. By design, as with the integration form: a signed-in session decides where a stored credential goes. It can point an entry that keeps its stored credential at another URL, and the next refresh sends the credential there; it can also name any stored secret as `token: $secret:<name>` (`/api/secrets/keys` lists the names). The logger redacts by text, not by field name: a header map or a field such as `apiKey` or `Authorization` would be written as it is, and no line logs one today |
| **D**oS | Unbounded caches/maps; oversized bodies; refresh wedge; filling the disk through the public icon cache | FIFO-bounded caches (`cache.js`) + rate-limiter keys; 1MB body limit + per-route size caps (zod 512KB, secrets 8KB, cron field caps); refresh-loop liveness in `/api/health`/`/readyz`; `/api/icons/cached` fetches only icon-repository URLs, rebuilt from an allowlist so query-string variants share one file (`icon-sources.js`), caps each icon at 512 KB and the whole cache at 50 MB (`JAGHELM_ICON_CACHE_MAX_MB`) with least-recently-used eviction, counted from disk at boot; at most 8 fetches from the CDN run at once with 256 more waiting (a 503 with `Retry-After` past that), a body is held only until it is on disk and every response streams from the file, so icon bodies in memory stay under 4 MB however many misses arrive or however slowly clients read (`icon-cache.js`) | Single instance — a determined LAN attacker can still load it; memory still grows with the number of open connections, as for any route (measured: 4,000 concurrent requests for refused URLs take the process from 64 MB to about 130 MB RSS, the same number of icon misses to about 190 MB). Anyone who can reach the port can churn the icon cache (evicting the dashboard's icons, which are then fetched again), fill the fetch queue so other misses get a 503 for a while, and make the server fetch allowlisted icons from jsDelivr |
| **E**levation | SSRF via an integration URL → reach internal services / cloud metadata | `assertSafeUrl` enforced **inside** both `safeFetch` clients (blocks the metadata IP and 0/8 however they are written: decimal/hex/octal IPv4, or IPv4-mapped/-compatible IPv6, which is checked as its IPv4 address; private nets in strict mode); operator infra is `trusted` and exempt only from the private-net block. The app-tab embed check (`/api/embed-check/:tabId`, `embedCheck.js`) fetches only a URL saved as an app tab, looked up by tab id, with no cookie or credential, follows redirects only on the same host (hostname and port) with `assertSafeUrl` on every hop, reads only a 2xx answer, and returns at most one framing header line (clipped to 200 characters), never the body | `/api/integrations/test` is a deliberate reachability oracle — now rate-limited + audited; the embed check is a weaker one for a signed-in user who saves an app tab (it answers unreachable, timed out or a framing header), bounded by its cache and 30 reads a minute; DNS-rebinding is a documented TODO |

## The deliberate sharp edges (accepted, documented)

- **Open by default** (no password ⇒ unauthenticated) and **`network_mode: host`**
  in the published compose — both are LAN-convenience defaults with loud warnings.
  Set `DASH_PASS` and/or a bridge network + published port to close them.
- **`/api/integrations/test`** can probe any host the server can reach. It's behind
  auth, rate-limited (10/min/IP), and audit-logged, but remains an oracle by design
  (you have to be able to test a connection before saving it).
- **`/metrics`** is public by convention so Prometheus can scrape it; it exposes
  request counts/timings and refresh health, never secrets or config values.
- **`/api/icons/cached`** is public because an `<img>` can't send the header
  token. It fetches and serves only icon-repository icons (Dashboard Icons and
  selfh.st, SVG/PNG/WebP), never follows a redirect elsewhere, and serves them
  with `default-src 'none'; style-src 'unsafe-inline'; sandbox` and `nosniff`,
  so an SVG opened directly can't run script on JagHelm's origin.
- **Global login lock = a small lockout-DoS surface**: an attacker who can reach
  `/login` can deliberately trip the global failure lock (50/15min) to deny the
  real admin for the window. For a single-user app this is the right tradeoff —
  far better than letting an IP-rotating brute force through — and it self-clears
  in 15 min, but on an internet-exposed instance prefer a reverse-proxy WAF/IP
  allowlist in front of `/login`.

See `docs/security/INCIDENT-RUNBOOK.md` for what to do if a secret is exposed.
