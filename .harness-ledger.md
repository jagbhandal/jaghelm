# JagHelm harness ledger — captured failures (L1)

Per `docs/mobile/DESIGN.md` "The holds/cracks ledger". Each row is a real
captured gap; promoting it to an enforcer stamps `evidence[pillar]` in
`.harness.yml`.

**Scope:** this ledger tracks gaps in the **reused data layer** — the three
files the future `MobileApp.jsx` shell will import directly:
`src/hooks/useData.js`, `src/api/client.js`, and `src/storage/index.js`.
These are the only files that must be fully base-aware / seamed before mobile
can ship. Everything else is desktop-shell (see OUT-OF-SCOPE section below).

## #1 — raw `/api` literal bypasses the base resolver (Phase 1)

- **Pillar:** legibility
- **File (correct attribution):** `src/hooks/useData.js` → `uploadFile()` (NOT
  `src/api/client.js` — verified against the current tree per the spec's
  "Ground-truth file references" section).
- **Gap:** `uploadFile` builds its URL from a hardcoded `` `/api/upload?type=${type}` ``
  instead of `getApiBase()`. Every other data-layer URL (reads, writes, and the
  icon proxy) now resolves through `getApiBase()`; this is the single remaining
  **data-layer** literal.
- **Why not fixed in Phase 1:** `uploadFile` is web-only — mobile does no file
  uploads (DESIGN.md "Icon Rendering §"). Making it absolute now would be inert
  code with no consumer.
- **Residual / promotion rule:** if a mobile phase ever adds upload, route it
  through `getApiBase()` (one-line change) and close this row.
- **Status:** OPEN (tracked, intentional).

## OUT-OF-SCOPE — desktop-shell raw `/api` literals (intentionally not base-aware)

The mobile app will use its own `MobileApp.jsx` shell with bottom-tab
navigation. It reuses ONLY the data-layer hooks above. The following
desktop-shell files are NOT imported by the mobile entry and are intentionally
excluded from base-aware scope:

| File | Raw `/api` locations | Why excluded |
|------|----------------------|--------------|
| `src/App.jsx` | (no token localStorage read — removed; `authToken` state initialises to `''` and is seeded post-boot via `initAuthToken()`) | Desktop shell only — imported solely by `src/main.jsx`. The authoritative async token path is `client.initAuthToken()` via `secureStore` (see Phase 2 note below). |
| `src/hooks/useConfigPersistence.js` | 4 × `/api/display-config` (lines 42, 82, 92, 117) via `apiFetch` | Desktop display-config persistence — consumed only by `App.jsx` (confirmed by grep; no other importer). |
| `src/components/settings/*` | Multiple raw `/api/` literals in SectionsTab, SecurityTab, IntegrationsTab/*, ServicesTab | Desktop-only settings UI — mobile renders none of these tabs. |

**Every raw `/api` literal in the repo is now accounted for:** one open gap in
the reused data layer (gap #1 above) and three desktop-shell groups listed
above.

**Phase 2 forward note:** when `MobileApp.jsx` is built, it MUST call
`client.initAuthToken()` (secureStore-backed, async) for token boot — NOT copy
`App.jsx`'s sync `localStorage.getItem` pattern, which is desktop-only and
bypasses the `secureStore` seam.

# Phase 2 — Mobile scaffold + shell (captures)

Honest numbers: the mobile app builds a **DEBUG** APK here (`mobile/android/app/build/outputs/apk/debug/app-debug.apk` produced via `./gradlew assembleDebug`). **Release signing is NOT verified in Phase 2** — keystore + signed APK are Phase 6 (human secret). On-device runtime is NOT exercised in Phase 2 (agents are sandboxed, no emulator available here); it will be verified on the human's phone and is out of Phase 2 scope.

## #2 — desktop index.html still loads fonts from a CDN (context, not promoted)

- **Pillar:** legibility / autonomy
- **File:** `index.html` (desktop root) — `fonts.googleapis.com` + `fonts.gstatic.com` `<link>`.
- **Gap:** desktop fonts are CDN-hosted; mobile REQUIRES `font-src 'self'`, so Phase 2 **bundles the three families locally** (`mobile/src/fonts/*.woff2`, `mobile/src/styles/fonts.css`) and the mobile CSP is tight. The desktop CDN font link is intentionally untouched (desktop is out of mobile scope and its server CSP already allows the Google Fonts origins).
- **Residual:** if desktop ever wants offline/CSP-tight fonts, reuse `mobile/src/styles/fonts.css`.
- **Status:** OPEN (desktop), CLOSED for mobile.

## #3 — SDK 36 (scaffold default) builds here; AGP/Gradle version pin deferred to Phase 6

- **Pillar:** verification / enforcers
- **Note:** the Capacitor 8 scaffold writes compile/target **SDK 36** (matching DESIGN.md "Toolchain / SDK" preference). The build host has platforms android-36 + build-tools **36.0.0** installed, and `assembleDebug` builds clean on 36 with the full plugin set (`@capacitor/app`, `@capacitor/preferences`, `capacitor-secure-storage-plugin` → `androidx.security:security-crypto`). What remains is pinning explicit AGP / Gradle / Kotlin versions in `android/variables.gradle` for reproducible *release* builds — a tracked **Phase 6** follow-up.
- **Verified:** `assembleDebug` → `app-debug.apk` on SDK 36 (debug only; release signing is Phase 6).
- **Status:** OPEN (AGP/Gradle pin → Phase 6).

## #4 — @shared alias, not an extracted workspace package (deferred ADR)

- **Pillar:** gc / context
- **Gap:** mobile reuses `src/` via a single Vite `@shared` alias rather than an internal `@jaghelm/data-layer` workspace package. Promoting it forces a desktop-side import refactor for zero immediate benefit.
- **Promotion rule (ADR):** promote `@shared` → internal workspace package when a third consumer appears.
- **Status:** OPEN (tracked, intentional).

## #5 — native-HTTP-default transport (context/gc evidence)

- **Pillar:** context / autonomy
- **Note:** transport default is Capacitor native HTTP (`CapacitorHttp.enabled: true`) — bypasses CORS, reads ETag, needs ZERO server/CSP change. The Express `CORS_ORIGIN` + `CSP_CONNECT_EXTRA` env path is the documented FALLBACK only (and widens reachable origins — `https://localhost` is attacker-spoofable from non-browser clients; bounded by the custom `x-auth-token` header / non-credentialed CORS). Decision is explicit and testable via `mobile/src/nativeHttp.js`.
- **Status:** RESOLVED (documented decision).

# Phase 3 — Read-only UX screens (captures)

## #6 — server has NO incident model → incidents derived client-side

- **Pillar:** determinism / context
- **Note:** the backend exposes raw `/services`, `/ups`, `/cron/status` bodies but no "incident" object. Active incidents + degraded-subsystem state are derived deterministically in `mobile/src/data/derive.js` (pure, table-tested) — `deriveIncidents`/`deriveSubsystems`. Incident ids are stable (`service:<uid>` / `ups:apcups` / `cron:<node>:<job>`) and ranked service→ups→cron then by id, so the list is order-stable across input reordering. Ready for the Phase-5 real push-history feed.
- **Status:** RESOLVED (documented; pure module).

## #7 — `uptime24` (raw body) vs desktop `ServiceCard.uptime` (upstream rename)

- **Pillar:** context / correctness
- **Note:** per-service 24h uptime is the scalar `service.uptime24` (0–1, may be null) in the RAW server body; desktop `ServiceCard` reads a renamed `.uptime` after its own mapping. Mobile consumes the raw `uptime24` directly (never `.uptime`) — flagged repeatedly in briefs because copying a desktop idiom would silently render `undefined`. Enforced by tests asserting `uptime24` rendering.
- **Status:** RESOLVED (documented; the single most likely correctness slip, guarded).

## #8 — `/history` is node-level CPU/MEM/DISK series, not per-service uptime

- **Pillar:** context
- **Note:** `/history` returns node-level metric series keyed `"${nodeKey}:${metric}"`, NOT per-service uptime series. So an incident's "24h" value is the `uptime24` scalar, not a sparkline series. IncidentCard renders the scalar (Sparkline path is conditional/deferred). Prevents a wrong assumption that history feeds per-service charts.
- **Status:** RESOLVED (documented).

## #9 — icon-extraction deliberately NOT done (YAGNI)

- **Pillar:** simplicity / reuse
- **Note:** the plan permitted extracting `src/hooks/serviceIcon.js` shared by desktop+mobile, but only "if both consume it". Mobile keys icons off `display_name`, desktop off `.name` — different inputs → no shared extraction. Mobile calls `getServiceIcon` directly through the base-aware resolver (`getApiBase`), never a relative `/api` URL. Desktop `ServiceCard.jsx` untouched (byte-for-byte). Avoided a premature abstraction.
- **Status:** RESOLVED (YAGNI honored).

## #10 — visual pass is a DEV TOOL, not shipped (Playwright harness)

- **Pillar:** verification / supply-chain
- **Note:** `mobile/visual/` (fixtures/mount/render.html/shoot.mjs) renders each screen to PNGs (`out/`, gitignored) for human eyeballing. NOT imported by the app, NOT in `npm run build`, NOT in `npm test`/CI. Playwright is NOT a `mobile/package.json` dependency (the OSS bundle stays install-free) — `shoot.mjs` does a bare `require('playwright')`, resolved at run time via an externally-provided playwright (locally `NODE_PATH=/tmp/shotter/node_modules`; Chromium auto-found from the ms-playwright cache). Gap: the harness can't run in a clean checkout without playwright present — acceptable for a dev tool, documented in the file header.
- **Status:** OPEN (intentional dev-tool gap; not promoted to CI).

## #11 — controller deviation: `formatDayLabel` replaces hard-coded "Today"

- **Pillar:** correctness / determinism
- **Note:** the plan hard-coded a literal `"Today"` heading at the Alerts day-group render site, discarding `groupByDay`'s real output (a latent Phase-5 bug: every day would read "Today"). Replaced with a PURE `formatDayLabel(dayKey, todayKey)` (Today/Yesterday/"Jun 25", `todayKey` injected so it's deterministically testable) mapped over ALL groups. Phase-3 data is all "now" → still shows "Today"; Phase-5 multi-day history will show correct labels. Plan's own constraint ("assertions are meaningful") governed the related circular `deriveIncidents` stability test, replaced with a hardcoded expected-order literal.
- **Status:** RESOLVED (deviation applied; trivially reversible).

## #12 — Overview/Alerts incident rendering: compact rows, not IncidentCard (FLAG)

- **Pillar:** reuse / UX
- **Note:** the Alerts brief TEXT said "reuse IncidentCard" but the brief's OWN reference code hand-rolls compact `alert-row`s. IncidentCard is a heavy expanded card (uptime spark + Open) suited to Overview, not a scrollable active/history list. Implementation uses compact rows for the lists (distinct component, not a duplicated IncidentCard) — satisfying the spirit (no IncidentCard duplication). FLAGGED for Jag to consciously accept or override (trivially reversible to cards).
- **Status:** OPEN (FLAG — awaiting Jag's accept/override).

## #13 — root `.gitignore` `data/` rule masked `mobile/src/data/`

- **Pillar:** supply-chain / hygiene
- **Note:** a pre-existing root `.gitignore` `data/` pattern silently un-tracked the new source dir `mobile/src/data/` (derive.js/useDashboard.js/groupByDay.js). Fixed with a scoped negation `!mobile/src/data/**` (verified via `git check-ignore` that future files in the subtree are trackable). Caught by an implementer when files wouldn't stage — a reminder that broad gitignore globs can swallow real source.
- **Status:** RESOLVED.
